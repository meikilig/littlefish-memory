# 01 · 架构

## 一句话

**说出来的话先进流水，夜里复盘成记忆；记忆按"该记多牢"分四级，每次说话时按预算装配进上下文；白天的原话另存一份"一天一页"的档案，只在被问到时才翻。**

```
用户说的话
   │
   ├─► memory.add()        ─► memory 表（四级 + 印象分）   ← 长期记忆
   ├─► life.log_chat()     ─► life_log 表（当天流水）      ← 只作当天上下文
   └─► recall.on_message() ─► 命中就 hits+1，够线就升级

每一轮开口之前：
   memory.render()  ─►  <recall> + 七桶，总长 ≤ inject_max_chars

夜里：
   nightly 把当天流水提炼成几条记忆；原话归成 archive_page（一天一页，永久）
```

## 数据表

| 表 | 存什么 | 谁写 |
|---|---|---|
| `memory` | 记忆本体：`text/title/kind/importance/retention/clarity/tier/hits/last_hit_at/pinned/archived` | `memory.add()`、`recall`、`memory.decay_once()` |
| `memory_token` | 倒排索引：词 → 记忆 id（bigram + 同义词归一） | `memory.add()`（同一事务里重建） |
| `life_log` | 当天流水：`ts/kind/summary/detail/conv_key/consumed` | `life.log_chat()`、`life.log_life()` |
| `room` | 每扇窗口的门牌：`conv_key/name/uid/msg_count/last_seen` | `life.touch_room()` |
| `archive_page` | 档案页：`day/conv_key/kind/title/text/chars`，`UNIQUE(day,conv_key,kind)` | `archive.build_day()`、`archive.put_diary()` |
| `archive_token` | 档案倒排：词 → 页 | `archive.put_page()` |
| `kv` | 零散状态（水位、当天账、上次扫描时间…） | 各处 |

`db.py` 的 `SCHEMA_VERSION = 9`，迁移按版本号逐级补列 / 建表，不重建库。

## 四级怎么定

落位不看"被提起过几次"，只看**类型**与**印象分**（`memory.suggest_tier`）：

| 条件 | 落位 |
|---|---|
| `pinned` / `is_first` / `kind in (manual,)` | **L4 刻下** |
| `kind in (promise, conflict, firstMeet, fact)` 或 `importance >= 70` | **L3 长久** |
| 主人说的 / 她自己说的 / `kind=emotion` 或 `importance >= 50` | **L2 记得** |
| 其它 | **L1 新鲜** |

### 升降级

升级（`recall._want`）：

```
pinned or is_first                    → 4（L4 永不降级，也不看时间）
hits >= promote_hits.l4               → 4
hits >= promote_hits.l3 且 last_hit_at 在 hold_days.l3 内 → 3
hits >= promote_hits.l2 且 last_hit_at 在 hold_days.l2 内 → 2
否则                                   → 1
```

**为什么升级还要看"最近"**：只按累计次数判的话，`sweep()` 把一条旧事降到 L1 的当天，`promote_by_hits()` 又会因为累计 hits 够线把它原封不动弹回去 —— 降级等于没写。加时间窗之后，久到降级了就不再自动弹回；人哪天真又说起它，`last_hit_at` 刷新了，自然升回去。

降级（`memory.decay_once`，每天 `memory.daily_hour` 跑一次）：按 `retention` 与 `clarity` 递减，`fuzzy_after_days` 后转模糊，`forget_after_days` 且从没被想起过才归档（`archived=1`，不物理删）。

## "被想起"怎么算

`recall.on_message(text, ctx)`：

1. 太短（< 4 字）不检索 —— "在吗"没有检索价值；
2. `memory.search()` 本地 bigram 倒排取候选；
3. 候选要过三道闸：`matched >= recall_min_hits`、**`memory.scene_ok()`（跨窗口隔离）**、`last_hit_at` 不在 `recall_same_topic_hours` 内（防同一话题连刷升级）；
4. 取前 `recall_topn` 条 → `memory.bump_hits()` → `promote_by_hits()`。

它**只记账，不写新记忆**。返回的那几条会作为 `<recall>` 段进这一轮的注入。

## 注入怎么装配

```
memory.render(platform, budget=inject_max_chars[platform], ctx=..., recall=picked)
   ├─ _recall_block(picked)        150~200 字，「这是刚才想起的过去的事，不是现在要你做的事」
   ├─ budget -= len(recall) + 2
   ├─ _load_rows()                 只取 archived=0、过 scene_ok 的
   └─ build()                      七桶按优先级两遍装配
```

七桶按优先级占位（先占位再填内容），单行超预算时截断而不是弃整桶。装不下的桶只留标题。
`recall_block_chars = 0` 可以整体关掉 `<recall>`。

## 流水与复盘

- `life.log_chat()` 把一句话写进 `life_log`；**同窗口 600 秒内折叠成一条**（折叠时把 `ts` 更新成现在，否则链条永远闭合不了）。
- 流水**不进注入**，只在夜间复盘时作为"今天发生过什么"的材料。
- 复盘成功后 `life.consume(ids)` 标记已提炼；`life.purge()` 只删 `consumed=1` 且超期的行。

## 档案室

- 粒度：**一扇窗一天一页**（聊天一页、做过的事一页、日记一页）。
- 索引：正文分词进 `archive_token`；查询先精确认日期（`10月31日` / `十月三十一日` / `2026-10-31` / `昨天`），认出来就直接翻那天的页；认不出来才走倒排。
- 单字查询（`B站` 归一后只剩「站」）走 `LIKE` 兜底。
- 长页只回「开头 2/3 + 中间省 N 字 + 结尾 1/3」，保证"最后两句"这种问法能答。
- **只翻本窗口**：`open_page(page_id, conv_key)` 里页的 `conv_key` 与请求者不符就返回"那页不在这扇窗里"。

## 模块边界

模块之间**不 import**，只走 `bus.emit()`（`bus.py` 是 60 行的极简实现）。这条规矩是为了让任何一块能被单独抽走 —— 这个仓库本身就是那么来的。
